# VPN / CyberGhost WebAdmin integration

This fork can run the Stremio runtime behind **CyberGhost VPN** using a dedicated **Gluetun** gateway while keeping WebAdmin and Pi-hole directly reachable from the LAN.

## Security model

- Only `stremio-libtorrent-server` shares the Gluetun network namespace.
- VPN mode is **fail-closed**: if the tunnel is stopped or fails, Stremio does not fall back to the normal host WAN.
- WebAdmin and Pi-hole remain on the normal Docker/LAN network.
- The Gluetun control API is not published to the host and is protected by a private API key generated by `start-vpn.sh`.
- CyberGhost credentials, client certificate and private key are stored in the private `vpn-data` Docker volume. The WebAdmin API never returns the saved secret values.
- CyberGhost does not provide VPN-side port forwarding. For that reason VPN mode deliberately does not publish the Stremio BitTorrent listen port on the host.

## Requirements

1. Docker + Docker Compose plugin.
2. `/dev/net/tun` available on the Docker host.
3. A CyberGhost subscription with a generated manual OpenVPN configuration.
4. From the CyberGhost manual configuration, keep:
   - generated OpenVPN username;
   - generated OpenVPN password;
   - `client.crt`;
   - `client.key`.

Do not use your normal CyberGhost account password in place of the generated OpenVPN credentials.

## First-time setup

Update the repository and start the normal stack first:

```bash
git checkout main
git pull --ff-only origin main
sh start.sh
```

Open WebAdmin on port `8090`, select **VPN**, and enter the CyberGhost OpenVPN material. UDP is the recommended default. Country is optional; leaving it blank lets Gluetun select from the provider's available servers. A hostname is also optional and is intentionally left blank by default because it is a narrower and more fragile filter.

Use **Save** to persist the material without changing the current deployment mode.

Then start VPN mode on the Docker host:

```bash
sh start-vpn.sh
```

`start-vpn.sh`:

- detects the current LAN IPv4 address;
- creates `.vpn-control-key` on first use with mode `0600`;
- pulls the Server, WebAdmin, Pi-hole and VPN gateway images;
- starts `compose.vpn.yaml` using the same persistent data volumes;
- routes only Stremio through Gluetun.

Return to WebAdmin → **VPN**. The page shows tunnel state, public VPN address, kill-switch state, provider/protocol and traffic counters.

## WebAdmin controls

### Connect / Disconnect / Reconnect

The buttons call Gluetun's authenticated control API. **Disconnect** does not switch Stremio back to the host WAN. It intentionally leaves Stremio blocked by the VPN firewall until **Connect** is used again.

### Save & Apply

Configuration is written to `vpn-data` and Gluetun is restarted. The Stremio and WebAdmin data volumes are not deleted.

### Test protection

The protection test compares:

1. direct WebAdmin/host public egress;
2. Gluetun's reported public VPN address;
3. public egress observed from inside the Stremio container.

When the VPN is running, a protected result requires the Stremio egress to match the VPN address and differ from the normal host WAN address. When the VPN is deliberately stopped, the test expects Stremio to have no public egress.

## Switching back to direct mode

Run:

```bash
sh start.sh
```

The launcher uses `--remove-orphans`, so the Gluetun gateway is removed while all named volumes remain intact. The next `sh start-vpn.sh` reuses the saved VPN configuration.

## Optional selection

The WebAdmin supports:

- OpenVPN UDP or TCP;
- country filter;
- exact server hostname filter;
- LAN CIDRs allowed outside the VPN tunnel.

Default allowed LAN ranges are:

```text
192.168.0.0/16,10.0.0.0/8,172.30.0.0/24
```

Do not expand these ranges to public networks unless you understand the leak implications.

## Troubleshooting

Check stack state:

```bash
VPN_CONTROL_API_KEY="$(cat .vpn-control-key)" docker compose -f compose.vpn.yaml ps
```

Check VPN logs from the host:

```bash
docker logs --tail=200 stremio-gluetun
```

Or use the **VPN Logs** panel in WebAdmin.

Confirm Stremio shares Gluetun's network namespace:

```bash
docker inspect stremio-libtorrent-server \
  --format '{{.HostConfig.NetworkMode}}'
```

The value should start with `container:` and identify the Gluetun container.

If `/dev/net/tun` is missing, enable TUN support on the Docker host before starting VPN mode.
